Boundary rule: each context owns its writes and invariants. Other contexts use a public command/query interface or durable events—not internal repositories or direct table mutation.

Architecture findings

  • Strong base: coarse web/API/worker runtimes, explicit feature modules, PostgreSQL transactions, substantial tests and Redis fallback.
  • Critical gap: CI validates type/build but does not gate lint and tests.
  • High coupling: order and B2B modules import many capabilities; schema ownership is implicit across 209 Prisma models.
  • Scale limit: single-host Nginx topology plus per-process memory rate limiting and cache behavior.
  • Operations gap: liveness-only health, uneven structured logs, missing correlation and workload SLOs.

Communication rules

SynchronousAuth · checkout decision · inventory/price validation · local order transition · payment intent
AsynchronousNotifications · search index · reports · ERP/courier sync · analytics · long jobs

Delivery model: transactional outbox + at-least-once delivery + idempotent consumer + bounded retry + terminal recovery.
