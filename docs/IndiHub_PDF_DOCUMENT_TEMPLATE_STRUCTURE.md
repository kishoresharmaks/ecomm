# 1HandIndia PDF Document Template Structure

Last verified: July 27, 2026.

## Purpose

This document is the manual editing reference for every PDF generated by the 1HandIndia application.

It describes:

- The common visual structure shared by generated PDFs.
- The exact section order for each document type.
- Required, optional, and dynamically generated fields.
- Which source file controls each part of the PDF.
- Which PDFs are external uploads or provider-generated files and must not be re-templated.

## Architecture Decision

All application-generated PDFs use one PDFKit renderer:

`apps/api/src/documents/professional-pdf.ts`

Document-specific files only prepare data and sections for that renderer:

| Document family | Source file |
| --- | --- |
| Tax and statutory documents | `apps/api/src/tax/tax-document-pdf.ts` |
| B2B proforma and receipt voucher | `apps/api/src/b2b/b2b-document-pdf.ts` |
| Seller settlement statement | `apps/api/src/finance/seller-statements.service.ts` |
| Embedded brand logo | `apps/api/src/documents/professional-pdf-logo.ts` |

Do not create a separate PDF engine for a new document. Add a thin document adapter that calls `renderProfessionalPdf`.

## Common PDF Structure

Every generated PDF uses the following page structure.

### 1. Page Configuration

- Page size: A4 portrait.
- Width: 595.28 points.
- Height: 841.89 points.
- Left margin: 42 points.
- Right margin: 42 points.
- Top margin: 36 points.
- Bottom content reserve: 50 points.
- Automatic multi-page pagination.
- Repeated brand header on every page.
- Repeated page-number footer on every page.

### 2. Brand Header

Left side:

1. Approved 1HandIndia logo.
2. `1HandIndia` brand name.
3. One of these captions:
   - `Quality assured marketplace` for seller-issued documents.
   - `Marketplace document service` for platform-issued documents.

Right side:

1. Document title.
2. Document number, when available.

Below the title row:

1. Orange brand divider.
2. Issuer legal or operational name.
3. Issuer caption, when configured.
4. Status pill, when configured.

### 3. Optional Subtitle

The subtitle explains the legal or operational purpose of the document.

Examples:

- A proforma explicitly states that it is not a tax invoice.
- A bill of supply states that GST is not charged separately.
- A commercial invoice states that GST has not been collected.

### 4. Metadata Panel

Metadata is rendered as responsive two-column label/value fields unless the document requests one column.

Typical metadata includes:

- Document number.
- Related order or payout number.
- Issue date.
- Supply date.
- Validity or payment date.
- Currency.
- Document status.

### 5. Party Cards

Up to two party cards are displayed side by side.

Each party card supports:

- Party label.
- Legal or display name.
- GST registration details.
- GSTIN.
- Postal address.
- Additional contextual lines.

### 6. Supported Content Sections

The shared renderer supports four section types.

#### Fields

Used for grouped label/value information.

Examples:

- Delivery and transport information.
- Payment information.
- Statutory references.
- Cash collection offsets.

#### Table

Used for line items and transaction records.

Features:

- Branded dark table header.
- Alternating row background.
- Configurable column widths and alignment.
- Automatic text wrapping.
- Automatic row-height calculation.
- Repeated table header after a page break.
- Empty-state text when no rows exist.

#### Totals

Used for financial summaries.

Features:

- Label/value rows.
- Right-aligned amounts.
- Optional emphasized row.
- The final row is emphasized automatically.

#### Notes

Used for legal, operational, or explanatory text.

### 7. Footer

Optional document-specific footer notes are rendered before the standard footer.

The standard footer contains:

- Computer-generated document notice.
- Associated-record verification guidance.
- `Page X of Y` pagination.

## Tax Invoice Structure

Source: `apps/api/src/tax/tax-document-pdf.ts`

### Header

- Title: `Tax Invoice`.
- Document number: issued tax-invoice number.
- Status: current tax-document status.
- Issued by: seller legal name.
- Caption: `Seller-issued document powered by 1HandIndia`.
- Subtitle: transaction document issued from recorded seller and order tax details.

### Metadata

1. Document number.
2. Order number.
3. Issue date.
4. Supply date.
5. Supply type.
6. Reverse-charge status.
7. Currency.
8. Number of line items.

### Supplier Card

- Seller legal name.
- Seller GST registration classification.
- Seller GSTIN or `Not provided`.
- Seller address snapshot.

### Recipient Card

- Buyer legal name.
- Buyer GSTIN or `Not provided`.
- Buyer address snapshot.
- Place-of-supply state code.

### Item and Tax Details Table

| Column | Dynamic content |
| --- | --- |
| Description / SKU | Product or service description and SKU/reference |
| HSN/SAC | HSN/SAC code and tax classification |
| Qty | Quantity and unit-of-quantity code |
| Taxable | Taxable value |
| GST | GST rate and CGST/SGST/IGST/cess breakdown |
| Total | Final line value |

### Totals

1. Taxable value.
2. CGST.
3. SGST.
4. IGST.
5. Cess.
6. Total tax.
7. Invoice value, emphasized.

### Conditional Statutory References

Displayed only when values exist:

- Invoice Reference Number (IRN).
- Acknowledgement number.
- Acknowledgement date.
- E-way bill number.

## Bill of Supply Structure

Source: `apps/api/src/tax/tax-document-pdf.ts`

The bill of supply uses the same structure as the tax invoice with these differences:

- Title: `Bill of Supply`.
- Subtitle: `GST is not charged separately on this bill of supply.`
- Tax values normally reflect the applicable non-separate-tax treatment.
- Seller registration may represent composition-scheme or other bill-of-supply eligibility.

Section order:

1. Header and legal subtitle.
2. Metadata.
3. Supplier and recipient cards.
4. Item and tax details table.
5. Totals.
6. Conditional statutory references.
7. Standard footer.

---

## Commercial Invoice Structure

Source: `apps/api/src/tax/tax-document-pdf.ts`

The commercial invoice uses the same tax-document layout with these differences:

- Title: `Commercial Invoice`.
- Subtitle: `No GST has been collected on this commercial document.`
- GSTIN values remain visible when recorded, but the document does not claim GST collection.

Section order:

1. Header and commercial-document subtitle.
2. Metadata.
3. Supplier and recipient cards.
4. Item details table.
5. Financial totals.
6. Conditional statutory references, when applicable.
7. Standard footer.

## Credit Note Structure

Source: `apps/api/src/tax/tax-document-pdf.ts`

The credit note uses the common tax-document layout and adds adjustment context.

### Additional Metadata

- Original document number.
- Adjustment reason, when recorded.

### Footer Requirement

The footer states that the adjustment document must be read together with the referenced original invoice.

Section order:

1. Credit-note header.
2. Adjustment subtitle.
3. Metadata including original document and reason.
4. Supplier and recipient cards.
5. Adjusted item and tax details.
6. Adjustment totals.
7. Conditional statutory references.
8. Original-invoice reference notice.

## Service-Booking Purchase or Tax Document Structure

Sources:

- Template: `apps/api/src/tax/tax-document-pdf.ts`.
- Service data mapping: `apps/api/src/tax/tax-documents.service.ts`.

Service-booking documents deliberately reuse the legal tax-document template rather than maintaining a separate service PDF design.

The actual document type can be a tax invoice, bill of supply, commercial invoice, credit note, or debit note according to the recorded transaction.

Service-specific dynamic values include:

- Service description.
- Booking or order reference.
- SAC code.
- Service quantity or unit.
- Taxable service value.
- GST rate and tax split.
- Service provider legal identity.
- Customer recipient details.
- Service-booking payment and adjustment values.

The section order remains identical to the selected tax-document type.

| --- | --- |

## B2B Final Invoice Structure

Sources:

- B2B data mapping: `apps/api/src/b2b/b2b.service.ts`.
- Final template: `apps/api/src/tax/tax-document-pdf.ts`.

The final B2B document does not use a separate invoice design. It uses the canonical tax-document renderer.

Depending on seller registration and transaction rules, the final document is one of:

- Tax invoice.
- Bill of supply.
- Commercial invoice.

Its structure is therefore the same as the corresponding tax-document structure documented above, with B2B buyer, seller, fulfilment, tax, and order snapshots supplied dynamically.

## Seller Settlement Statement Structure

Source: `apps/api/src/finance/seller-statements.service.ts`

### Header

- Title: `Seller Settlement Statement`.
- Document number: statement number.
- Status: current statement status.
- Issued by: `1HandIndia Seller Finance`.
- Caption: `Marketplace settlement and ledger document`.
- Subtitle: detailed settlement, deductions, offsets, and payout reconciliation.

### Metadata

1. Statement number.
2. Payout number or `Not linked`.
3. Period from.
4. Period to.

### Seller Card

- Seller business legal name or store name.
- Store name.
- GSTIN or `Not provided`.

### Issuer Card

- `1HandIndia Seller Finance`.
- Settlement support and payout reconciliation.
- INR display notice.

### Settlement Summary

1. Gross sales.
2. Commission.
3. GST on commission.
4. TDS.
5. TCS.
6. Seller settlement fee.
7. Refund adjustment.
8. Offsets and adjustments.
9. Net payable, emphasized.

### Product Order Payouts Table

| Column | Dynamic content |
| --- | --- |
| Order | Marketplace order number |
| Gross | Seller subtotal |
| Commission / Tax | Commission and GST on commission |
| TDS / TCS / Fee | TDS, TCS, and seller settlement fee |
| Net | Net payable amount |

Empty state: `No product order payouts are linked to this statement.`

### B2B Order Payouts Table

| Column | Dynamic content |
| --- | --- |
| Order | B2B order number |
| Buyer payable | Buyer payable amount |
| Commission | Marketplace commission |
| Seller payout | Seller payout amount |
| Status | Settlement status |

Empty state: `No B2B payouts are linked to this statement.`

### Service Booking Payouts Table

| Column | Dynamic content |
| --- | --- |
| Booking | Service booking number |
| Gross | Gross amount and inspection-fee amount |
| Deductions | Commission, GST, TDS/TCS, fee, and refund adjustment |
| Net payable | Net seller payable amount |
| Status | Service-settlement status |

Empty state: `No service payouts are linked to this statement.`

### Cash Collection Offsets

1. Service cash offsets.
2. Seller-collected COD offsets.

### Footer Notes

- Statement values are generated from append-only seller-finance ledger records.
- Reconciliation questions must quote the statement and payout numbers.

## External and Uploaded PDFs

The following documents are not generated by the shared template and must remain in their original format:

- Courier-provider shipping labels.
- Courier manifests.
- Courier-provider invoices.
- Buyer purchase-order uploads.
- Bank-transfer and payment-proof uploads.
- Proof-of-delivery uploads.
- Delivery evidence.
- Seller KYC and registration documents.
- Service field and completion evidence.

These files are uploaded by users or generated by external providers. Re-templating them could alter legal, operational, barcode, or provider-owned content.

## Manual Editing Guide

### Change Every Generated PDF

Edit:

`apps/api/src/documents/professional-pdf.ts`

Use this file for:

- Page margins.
- Brand colors.
- Typography.
- Header layout.
- Logo size and placement.
- Metadata cards.
- Party cards.
- Tables.
- Totals.
- Notes.
- Pagination.
- Standard footer.

### Change the Logo

Edit:

`apps/api/src/documents/professional-pdf-logo.ts`

Keep the fallback logo behavior in `professional-pdf.ts`.

### Change Tax Documents

Edit:

`apps/api/src/tax/tax-document-pdf.ts`

Changes here affect tax invoices, bills of supply, commercial invoices, credit notes, debit notes, service documents, and B2B final documents.

### Change B2B Proforma or Receipt Voucher

Edit:

`apps/api/src/b2b/b2b-document-pdf.ts`

### Change Seller Settlement Statements

Edit:

`apps/api/src/finance/seller-statements.service.ts`

## Required Verification After Template Changes

At minimum verify:

1. PDF starts with a valid `%PDF-` header.
2. Brand logo image is embedded.
3. All expected titles and sections are extractable.
4. Every page is A4 portrait.
5. No text block extends outside page boundaries.
6. Long tables repeat their header after page breaks.
7. Page numbering is correct.
8. Customer, seller, B2B, admin, and finance downloads use authenticated blob delivery.
9. API PDF tests pass.
10. Web typecheck, lint, tests, and production build pass when download UI changes.

## Ponytail Review

Lean already. Ship.

The current structure has one renderer and three thin domain adapters. Creating separate template engines or duplicate layouts would increase maintenance without adding value.
